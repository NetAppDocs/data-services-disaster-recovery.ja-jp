= Amazon EVS用のConsoleアカウントにNetApp Disaster Recoveryを追加
:allow-uri-read: 


[role="lead"]
NetApp Disaster Recovery はライセンス製品であり、使用する前に購入する必要があります。ライセンスにはいくつかの種類があり、ライセンスを購入する方法もいくつかあります。ライセンスにより、特定の期間にわたって特定の量のデータを保護する権利が付与されます。

災害復旧ライセンスの詳細については、link:../get-started/dr-licensing.html["Disaster Recoveryのライセンス設定"]を参照してください。



[[license-types]]
== ライセンス タイプ

ライセンスには主に 2 つの種類があります。

* NetAppは、ONTAPおよびVMwareリソースを使用したディザスタリカバリの評価に利用できるlink:../get-started/dr-licensing.html["30日間試用ライセンス"]を提供しています。このライセンスでは、無制限の保護容量を30日間利用できます。
* 30日間の試用期間後もDR保護が必要な場合は、製品版ライセンスをご購入ください。このライセンスは、NetAppのクラウドパートナーのいずれかのマーケットプレイスを通じて購入できますが、このガイドでは、Amazon AWS Marketplaceを使用してDisaster Recovery用のマーケットプレイスライセンスを購入することをお勧めします。Amazon Marketplaceを通じてライセンスを購入する方法について詳しくは、link:../get-started/dr-licensing.html["AWS Marketplace からサブスクライブする"]をご覧ください。




[[size-your-disaster-recovery-capacity-needs]]
== 災害復旧能力のニーズを予測する

ライセンスを購入する前に、保護する必要があるONTAPストレージ容量を把握しておく必要があります。  NetApp ONTAPストレージを使用する利点の 1 つは、 NetApp がデータを保存する際の効率性が高いことです。  ONTAPボリュームに保存されるすべてのデータ (VMware データストアをホストする VM など) は、非常に効率的な方法で保存されます。 ONTAP は、物理ストレージにデータを書き込むときに、圧縮、重複排除、圧縮という 3 種類のストレージ効率をデフォルトに設定します。最終的な結果は、保存されるデータの種類に応じて、1.5:1 から 4:1 のストレージ効率になります。実際、 NetAppは https://www.netapp.com/media/79014-ng-937-Efficiency-Guarantee-Customer-Flyer.pdf["ストレージ効率保証"^]特定のワークロード向け。

Disaster Recoveryでは、すべてのONTAPストレージ効率化が適用されたあとにライセンス用の容量が計算されるため、お客様にとってメリットがあります。たとえば、このサービスを使用して保護する100台のVMをホストするために、vCenter内に100テラバイト（TiB）のNFSデータストアをプロビジョニングしたとします。さらに、データがONTAPボリュームに書き込まれる際、自動的に適用されるストレージ効率化技術により、これらのVMが消費する容量はわずか33TiB（3：1のストレージ効率）になると仮定します。Disaster Recoveryのライセンスは、100TiBではなく33TiB分のみ必要となります。これは、他のDRソリューションと比較した場合、お客様のDRソリューションの総所有コストにおいて非常に大きなメリットとなります。

.手順
. 保護対象の VMware データストアをホストしている各ボリュームで消費されているデータ量を確認するには、各ボリュームに対してONTAP CLI コマンドを実行して、ディスク上の容量消費量を確認します。 `volume show-space -volume < _volume name_ > -vserver < _SVM name_ >` 。
+
例えば：

+
[listing]
----
cluster1::> volume show-space
Vserver : vm-nfs-ds1
Volume  : vol0
Feature                                Used      Used%
-----------------------------      --------     ------
User Data                           163.4MB         3%
Filesystem Metadata                   172KB         0%
Inodes                               2.93MB         0%
Snapshot Reserve                    292.9MB         5%
Total Metadata                        185KB         0%
Total Used                          459.4MB         8%
Total Physical Used                 166.4MB         3%

----
. 各ボリュームの*Total Physical Used*の値をメモします。これは、 NetApp Disaster Recovery が保護する必要があるデータの量であり、ライセンスが必要な容量を決定するために使用する値です。
